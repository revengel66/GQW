История чата (рабочий журнал)
Дата формирования: 2026-05-30 (Europe/Astrakhan)

Примечание:
- Полный «сырой» экспорт всей переписки из интерфейса у ассистента недоступен.
- В этом файле сохранен доступный рабочий журнал: основные запросы пользователя, ошибки, решения и принятые изменения.

Ключевой ход переписки:
1. Пользователь присылал результаты k6-прогонов и ошибки ingest:
   - connect refused к /api/analytics/frontend/ingest;
   - threshold crossed по http_req_failed;
   - ошибки summary-export из-за отсутствия пути reports/...
2. Пользователь формировал материалы для отчета/диплома:
   - перефразирование разделов;
   - таблицы по baseline/restart прогонам;
   - формулировки по нефункциональным требованиям, приватности, заключению, библиографии.
3. Далее фокус сместился на приложение (аналитический дашборд):
   - фильтры атрибутов/типов событий должны зависеть от выбранного периода и других фильтров;
   - долгие загрузки на больших диапазонах;
   - ошибки SQL lower(bytea) при filter-options;
   - рассинхрон глобальных фильтров/пресетов/метрик.
4. Пользователь попросил k6-скрипт для фоновой генерации пользовательских действий:
   - с устойчивостью к рестартам приложения;
   - позже фиксировались перегрузы пула соединений Hikari (Connection is not available...).
5. Обсуждение качества событий:
   - пользователь указал, что «технические» FRONTEND_* не должны жить как отдельные бизнес-события;
   - ошибки должны привязываться к существующим бизнес-событиям;
   - fallback-событие допустимо только для реально глобальных системных случаев.
6. Последний рабочий блок:
   - сравнение кодов событий БД и кодовой базы;
   - подтверждение, что активные бизнес-коды используются;
   - начаты правки по исключению «технических» событий из пользовательского слоя.

Внесенные изменения в код (по последнему блоку):
- FrontendAnalyticsIngestService:
  - отключено создание standalone FRONTEND_* событий;
  - frontend payload теперь сохраняется только как stage/metrics внутри родительского бизнес-события;
  - удалены связанные standalone-ветки и вспомогательные методы.
- EventTypeRepository:
  - добавлены методы выборки только пользовательских (non-system) типов событий.
- AnalyticsInsightsService:
  - словари event types переведены на non-system выборку;
  - в filter-options добавлена фильтрация скрытых системных event codes.
- FrontendAnalyticsDictionaryConfig:
  - отключен seed FRONTEND_* event types (оставлены stage/metric словари фронтенд-слоя).
